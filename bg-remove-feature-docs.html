Overview

The BG Remove feature lets users remove the background from any uploaded image using Cloudinary's AI transformation engine. Users can preview the result, then choose to save it as a new copy, overwrite the original, or download it directly. The feature lives inside the Playground — a multi-tool page that hosts image editing tools under a shared tab bar.

Step-by-Step Implementation

1
Shared Cloudinary Singleton
lib/cloudinary.ts

Before this feature, every API route (image-upload, video-upload, image-crop) was calling cloudinary.config(...) inline with credentials repeated in every file. Adding a fourth route (image-bg-remove) would have made it a fifth copy.

Problem

Cloudinary credentials and config() call duplicated across every API route file — violates DRY and CLAUDE.md shared-singleton rule.

Fix

Extracted a single lib/cloudinary.ts that calls cloudinary.config() once and exports the instance. All routes now import from this singleton. 

// lib/cloudinary.ts
import { v2 as cloudinary } from "cloudinary";

cloudinary.config({
  cloud_name: process.env.NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME,
  api_key:    process.env.CLOUDINARY_API_KEY,
  api_secret: process.env.CLOUDINARY_API_SECRET,
});

export default cloudinary;
2
Constants
lib/constants/bgRemove.ts · lib/constants/playgroundTools.ts

Per CLAUDE.md rules, any constant with reuse potential must live in lib/constants/ and never be defined inline in a component or route.

bgRemove.ts — exports

  • BG_REMOVE_EFFECT = "background_removal" — standard Cloudinary effect string
  • BG_REMOVE_FINE_EDGES_EFFECT = "background_removal:fineedges_y" — for fur, feathers, fine edge detail
  • BG_REMOVE_FOLDER = "images" — Cloudinary folder for saved copies
  • BgOutput type = "transparent" | "white"

playgroundTools.ts — exports

  • TOOLS array — drives the tab bar; adding a new tool here auto-adds its tab without touching the page JSX
  • ToolId union type — "crop" | "bg-remove"
3
Backend API — Background Removal
app/api/image-bg-remove/route.ts

This was the most complex part of the feature. The route handles three save modes and had two major technical hurdles.

Hurdle 1 — Cloudinary async transformation

Problem

Cloudinary's e_background_removal is asynchronous. When you build an on-the-fly transformation URL and immediately pass it to cloudinary.uploader.upload() as a source, Cloudinary returns a 400 error because the transformation hasn't been processed yet.

Fix — Server-side polling

Build the on-the-fly URL → poll it with GET requests every 2 seconds until Cloudinary returns 200 (cached and ready) → only then pass it to uploader.upload(). Cloudinary returns 423 while still processing.

Why GET and not HEAD: HEAD requests do not trigger Cloudinary's on-the-fly processing pipeline. Only a full GET request wakes it up. 

// Polls every 2s, up to 20 tries (~40s max)
async function waitForReady(url: string): Promise<void> {
  for (let i = 0; i < 20; i++) {
    const res = await fetch(url, { method: "GET" });
    if (res.ok) return;                 // 200 — cached, ready
    if (res.status !== 423) throw new Error(...); // unexpected error
    await new Promise((r) => setTimeout(r, 2000)); // 423 — still processing
  }
  throw new Error("Background removal timed out after 40s");
}

Hurdle 2 — PNG transparency / format issue

Problem

Cloudinary BG removal produces transparent areas, but the default output format follows the source image (often JPG). JPG does not support alpha transparency — so transparent areas came out solid black.

Fix — Separate transformation steps in the URL

Chain f_png as a separate step (slash-separated in the URL), NOT combined with e_background_removal in the same step. Combining them in one step causes a 400 error. 

// ✗ Wrong — 400 error
/e_background_removal,f_png/{publicId}

// ✓ Correct — separate steps
/e_background_removal/f_png/{publicId}

// White BG mode — fills transparency instead of forcing PNG
/e_background_removal/b_white/{publicId}

Three Save Modes

saveMode What happens DB change
preview Polls until ready, returns cached URL. No upload. None
copy Polls, uploads to Cloudinary as a new asset in images/ folder. New Image row created
overwrite Polls, re-uploads with same public_id + invalidate: true to clear CDN cache. Existing row updated (width/height)
4
UI Component — BgRemoveTool
components/playground/features/bg-remove/BgRemoveTool.tsx

Side-by-side layout (Original | Result) with:

  • Transparent / White BG toggle — switches the output mode. Changing it resets the result (stale result no longer matches).
  • Fine Edges checkbox — enables fineedges_y effect for images with fur, feathers, or intricate edge detail.
  • Animated processing skeleton — scanning line, spinning rings, pulsing corner brackets shown during the API poll.
  • Checkerboard background on the result panel — only in Transparent mode to reveal alpha areas. White mode uses a plain dark background.
  • Three action buttons (Save as Copy, Override Original, Download) — disabled until a preview result exists.
5
Playground Page Refactor
app/(app)/playground/[id]/page.tsx

The playground previously only had the Crop tool. We refactored it into a tab-based host:

  • TOOLS constant drives the tab bar — adding a new tool to the constant auto-adds its tab without any JSX changes.
  • Reads ?tool= query param on load, so external buttons (e.g. "BG Remove" in the Image Preview Modal) can pre-select a tool on arrival.
  • activeTool state switches between <CropTool> and <BgRemoveTool>.
  • Skeleton loader shown while the image is being fetched from the DB.
6
Image Upload Page — Navigation Change
app/(app)/image-upload/page.tsx
Problem

After upload, the API returned { publicId } (the Cloudinary public_id, e.g. images/abc123). The page navigated to /playground/images%2Fabc123. But the playground calls GET /api/images/{id} which does prisma.image.findUnique({ where: { id } }) — expecting a database UUID, not a Cloudinary public_id. Result: "Failed to load image."

Fix

Changed await prisma.image.create() to const image = await prisma.image.create() and returned { id: image.id, publicId }. The page now navigates to /playground/${data.id} — a clean UUID, URL-safe with no encoding needed.

7
Image Preview Modal — Shortcuts
components/image/ImagePreviewModal.tsx

Added BG Remove and Playground shortcut buttons alongside the existing Crop button. Each closes the modal and calls router.push with the appropriate ?tool= param so the playground lands on the right tab immediately.

Final Data Flow

User uploads image └─ POST /api/image-upload ├─ Upload to Cloudinary → gets publicId ├─ Save to DB → gets UUID (id) └─ Returns { id, publicId } └─ router.push(`/playground/${id}`) Playground page loads └─ GET /api/images/{uuid} └─ Returns ImageItem { id, publicId, title, width, height } User clicks "Remove Background" └─ POST /api/image-bg-remove { imageId, fineEdges, bgOutput, saveMode: "preview" } ├─ Build on-the-fly URL: │ https://res.cloudinary.com/{cloud}/image/upload │ /e_background_removal/f_png/{publicId} ├─ Poll with GET every 2s until 200 │ (Cloudinary returns 423 while processing) └─ Return { url } → shown in result panel User clicks "Save as Copy" └─ POST /api/image-bg-remove { saveMode: "copy" } ├─ waitForReady(url) ← already cached, returns immediately ├─ cloudinary.uploader.upload(url, { folder: "images" }) └─ prisma.image.create(...) → new DB row → appears in Home

Architecture Decisions

Decision Reason
Server-side polling instead of client-side Client would need to handle 423 retries and build/know the Cloudinary URL. Server polling keeps all Cloudinary logic backend-only and returns a guaranteed-ready URL to the client.
Separate URL steps for f_png Cloudinary requires transformation steps that depend on the result of a previous step to be slash-separated. Combining them in one step causes a 400.
Constants in lib/constants/ CLAUDE.md rule: any constant with reuse potential must be extracted. Keeps route files clean and allows future tools to reference the same effect strings.
Shared Cloudinary singleton CLAUDE.md rule: third-party SDK configs used in more than one file go in lib/<service>.ts. Prevents credential repetition and config drift.
TOOLS array drives tab bar Adding a new playground tool only requires one entry in playgroundTools.ts — no JSX changes needed in the page.
?tool= query param Allows external navigation (from modal buttons, links) to pre-select a specific tool without any shared state.
